# Update and Recovery

This page covers CLI updates, uninstall flows, install logs, and common recovery commands. Before updating or uninstalling, run:

```bash
chat2db version --json
chat2db status --json
```

## Update the CLI

Update the current CLI from the official CDN:

```bash
chat2db update --json
```

Update a target path:

```bash
chat2db update --target ~/.local/bin/chat2db --json
```

Verify afterward:

```bash
chat2db version --json
```

## Uninstall the CLI

Remove the current CLI binary:

```bash
chat2db uninstall --cli --yes
```

Preview without removing files:

```bash
chat2db uninstall --cli --dry-run --json
```

## Uninstall Chat2DB Pro / Local

Uninstall Pro:

```bash
chat2db uninstall --edition pro --yes --json
```

Uninstall Local:

```bash
chat2db uninstall --edition local --yes --json
```

Preview uninstalling both editions:

```bash
chat2db uninstall --edition all --dry-run --json
```

Uninstall commands verify app identity and preserve user data by default. Confirm the edition and target path before running them.

## Inspect Install Logs

Background installs write logs to the local state directory. Show install logs:

```bash
chat2db logs install --edition pro
```

Follow logs:

```bash
chat2db logs install --edition pro --follow
```

`logs` streams text. Do not pass `--json`.

## Clean Up Runtime State

Stop the Pro app, runtime, and MCP:

```bash
chat2db stop --edition pro --all --json
```

Stop Local:

```bash
chat2db stop --edition local --all --json
```

Stop only the CLI runtime:

```bash
chat2db runtime stop --edition pro --json
```

Disable only MCP:

```bash
chat2db mcp disable --edition pro --json
```

## Recovery Order

### 1. Confirm CLI Version

```bash
chat2db version --json
chat2db --help
```

If this documentation differs from `--help`, trust local `--help`.

### 2. Inspect Overall State

```bash
chat2db status --json
```

Read `next_action` first; it usually points to the shortest recovery command.

### 3. Runtime Issues

```bash
chat2db runtime status --edition pro --json
chat2db runtime start --edition pro --json
```

If it still fails, stop and start again:

```bash
chat2db runtime stop --edition pro --json
chat2db runtime start --edition pro --json
```

### 4. MCP Issues

```bash
chat2db mcp status --edition all --json
chat2db mcp restart --edition pro --json
```

If Pro / Local conflict on the MCP port, stop the unused edition:

```bash
chat2db stop --edition local --all --json
```

### 5. Datasource or SQL Issues

Confirm the datasource exists:

```bash
chat2db db datasources --edition pro --json
```

Test the connection:

```bash
chat2db db connection-test --data-source-id <data-source-id> --json
```

Then run a minimal query:

```bash
chat2db sql query \
  --data-source-id <data-source-id> \
  --database postgres \
  --schema public \
  --sql 'select 1' \
  --json
```

## Do Not Record

Do not paste these into public channels:

- database passwords
- MCP tokens
- Authorization headers
- JDBC URLs that contain credentials
- production administrator accounts
- full local paths that identify a personal machine

It is usually safe to keep command names, error codes, redacted endpoints, edition, version, and `next_action`.
